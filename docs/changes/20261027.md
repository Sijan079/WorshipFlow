# 2026-10-27: one stable captions link per church

Decided by grilling on 2026-10-27. Each entry gives the document, the version before
(From), and the version after (To), with the reason.

## 1. One stable viewer link per church (replaces the per-session link)

Reason: a congregation link has to be shared once, by QR code or message, and keep working
every week. A link that changes with each session cannot be printed or pinned, and a booth
crash meant sending listeners a new link.

### Architecture.md
From: "Public routes: login, auth callback, `/captions/live/{id}`, and `/c/{slug}`."
To: "Public routes: login, auth callback, `/captions/live/{token}`, and `/c/{slug}`." The
token is a random 32-character string, one per church, stored in `CaptionSettings`. The
viewer page and its feed `/api/captions/live/{token}` look the church up by token, then its
live session (or the latest ended one inside its one-hour hold). The old
`/captions/live/{session-id}` route is removed with no compatibility. The viewer checks every
2 seconds while live (changed to every second on 2026-10-27, see the latency record in `docs/worship/captions-latency.md`) and every 15 seconds while waiting or ended, pauses while the tab is
hidden, and refreshes when it becomes visible. There is no in-app rate limiter for the feed
yet; revisit if it serves more than a few dozen readers.

### Data-Model.md
From: caption models listed as unchanged.
To: Add `CaptionSettings` (one row per workspace: `workspaceId` unique, `viewerToken` unique,
`createdAt`, `rotatedAt`). The row is created the first time Share is opened. The token is
stored in plain text because it must be shown again as a QR code; it only grants read-only
caption text. Add `SHARE` to the `WorkspaceAction` enum.

### Access-and-Privacy.md
From: "Captions keep their own VIEW and OPERATE permissions."
To: Captions keep VIEW and OPERATE and add SHARE ("Share captions link"): open the Share
dialog and see, copy, and download the link and QR code. SHARE needs VIEW. Members have it
off by default; it is granted only in Settings → Membership, and the server checks it on every
Share request. Regenerating the link is Owner and Admin only and is not grantable. The public
viewer returns caption text only and never reads People, Ministry, or attendance data.
The token appears in server request logs because it is in the URL; it guards read-only text.

### Product.md
From: "Captions: optional module behind its own permission and flag."
To: Captions: optional module behind its own permissions and flag. One stable link per church
serves the congregation; Start and Stop only control whether captions are live.

## 2. Start takes over a dead session

From: Start fails with "already running" until the operator finds "Stop current session",
until the three-hour limit.
To: Start ends a live session whose heartbeat has been silent for 2 minutes or more and then
starts a new one. A session that is still sending heartbeats is never taken over.

## 3. Design rule: never nest cards

Reason: boxes inside boxes add borders and radii without adding meaning, and make small screens
and older eyes work harder. Raised while reviewing the Sermon Captions dialogs.

### DESIGN.md
From: "Prefer an open ledger, hairline rules, and spacing over extra containers." (no rule about
nesting).
To: Added "Never nest cards". A surface holds panels that extend vertically, divided by
hairline rules, with no border, radius, or shadow of their own; collapsible sections are stacked
full-width rows, indented per level. Exempt: form fields, buttons, a QR code's quiet zone, and
floating layers. Built in Sermon Captions (the help sections, the caption preview, and the QR
code in the Share dialog); Target elsewhere.

## 4. Stop is red

Reason: Stop captions ends the broadcast for everyone reading, so it should look unlike Start and
read as a deliberate action. It also asks for confirmation first.

### DESIGN.md
From: Buttons listed `ui-btn-danger` visibly red at rest as Target only.
To: Added `ui-btn-danger-solid` (solid red, white text, subtle elevation) as Built, for an action that
ends something live. `ui-btn-danger` keeps its quiet look (outline, red on hover) because Delete
buttons in Settings, People, the error list, and the Formatter use it; making it red at rest stays
Target.

### globals.css
From: only `.ui-btn-danger`.
To: Added `.ui-btn-danger-solid`. `.ui-btn-danger` is unchanged.

## 7. Rules settled in the 2026-10-27 grilling session

Reason: the Sermon Captions decisions clashed with a few older rules, and the owner confirmed each fix.

### DESIGN.md
- **Red.** From: "Red means an error only." To: "Red means an error, or an action that is destructive or
  disruptive to an operation (Stop, Delete)."
- **Purple.** From: "Purple is a signal: primary actions, focus rings, selection, the active tab, and accent
  text on hover." To: purple for primary actions, focus rings, selection, and the active tab. Accent text,
  links, and the hover and active states of secondary actions move to a secondary accent, sky blue
  `#0369a1`, as a **Trial** across the light workspace (one token, `--workspace-text-accent`, plus
  `--action-secondary-accent-*` and `--surface-highlight`; reversible by pointing them back at purple).
- **Motion.** From: animate `transform` and `opacity` only. To: two named exceptions (panel height, and the
  pulsing Live dot), and a continuity rule: things travel from where they were to where they are, and never
  jump (Target for the Regenerate button swap).
- **Typography.** From: headings are sentence case. To: dialog titles are in Title Case; headings inside a
  page and form labels stay sentence case.
- **Dialogs.** From: "an explicit Cancel in every dialog (Target)." To: Cancel on dialogs that ask or hold
  unsaved changes, Done on dialogs whose choices apply at once, and the close button always.
- **Confirmations.** From: "Destructive confirmations state what will be removed." To: every confirmation of
  a serious action says what will happen, defaults to Cancel, and reads **Yes, I am sure**.
- **Page contract.** Added item 8: pages that are not lists are one surface, or none, divided into panels.
- **Feel and reasoning.** From: twelve decisions with their long reasoning in `DESIGN.md`. To: twelve one-line
  decisions, the checklist, and the open question; the reasoning moved to `docs/design/decisions.md`, a log

## 8. Pre-deploy hardening of Sermon Captions

Reason: the security and deployment review found cases that only show on Vercel or under load.

### Architecture.md
From: "The feed has no in-app rate limiter yet."
To: The public feed is cached at the edge (1 second while live, 10 while waiting or ended, 30 for an
unknown link) and the proxy skips it, so a cached poll costs no function call. There is still no
per-address rate limiter, because a whole church shares one address and a limit would block real
listeners.

### Behavior
- **QR and link address.** From: `window.location.origin`, whatever address the admin browsed. To: `APP_URL`
  in production (https only), the browser's address in development. The team alias and per-deployment
  addresses are behind a Vercel login and would not open for the congregation.
- **Session limit.** From: three hours. To: four hours.
- **Retention.** From: lines erased only at the next viewer visit or Start. To: also erased by the daily
  keep-alive job, so the promise is "unreadable after one hour, erased within a day".
- **Azure over-quota.** From: a quota error looked like a bad key. To: its own plain message, kept apart
  from a busy service.
- **Dev against the live database.** The server reports when a development server is connected to a
  non-local database, so Start can ask for an extra confirmation.

## 9. Captions run in the background, with a floating live button

Reason: the booth operator should be able to use other pages, or switch windows, during a service
without the broadcast ending, and should be able to see that it is still live.

### Architecture.md and behavior
From: the captions session lived in the Captions page; leaving the page stopped it, and its heartbeat
used page timers.
To: the session lives in a provider above every workspace page. The heartbeat runs in a worker, the
screen is kept awake while live, and reloading, closing the tab or signing out asks first. The
microphone permission applies to every workspace page, not only the Captions page. Only people who can
view captions ask the server about sessions.

### DESIGN.md
From: "Purple is a signal: primary actions, focus rings, selection, and the active tab."
To: also one floating button that marks something running live for you. The floating live button is a
purple pulsing microphone at the bottom right (amber while recovering, red when it needs attention),
shown only while this browser is broadcasting and the Captions page is closed. It opens a panel with
Open Captions and Stop captions. Recorded in `docs/design/decisions.md`.

## 10. Event repeat rule, public flag, and service headcount (data and API)

Reason: roadmap step 6. The screens are a separate step.

### Data-Model.md
From: "`ChurchEvent`: remove `recurrence` and the `weekly*` fields. Replace with a repeat rule."
To: built additively. `ChurchEvent` gains `repeatKind` (NONE, DAILY, WEEKLY), `repeatWeekdays` (0 Sunday to
6 Saturday), `repeatUntil` (a local date, empty for "never"), `firstLocalDate`, `startLocal`, `endLocal`,
`spanDays` and `isPublic` (default false). `ChurchEventOccurrence` gains `edited`. `WorshipService` gains an
optional `headcount`. The old `recurrence`, `weekly*` columns and `EventRecurrenceKind` stay until a
deliberate cleanup, because removing them is destructive. The migration is
`prisma/migrations-current/20261028000000_event_repeat_rule`; it is not yet applied to the hosted database.

### Behavior
- A series is one stored occurrence row per date. Times are kept as local wall-clock times in the event's
  time zone, so they stay the same through daylight saving.
- Open-ended series keep four months of dates ahead; the daily keep-alive job adds the missing dates and
  never changes or removes anything. A series with an end date is limited to two years.
- An event may span up to 31 days. A repeating event must be shorter than the gap between its repeats.
- Changing the series updates and removes only future dates that were not changed by hand. Changing or
  cancelling one date marks it edited, and a series change then leaves it alone.
- Overlapping events still only warn.

### Access-and-Privacy.md
From: Events permissions are View and Create.
To: also Edit ("Edit and cancel events"), which needs View. Delete is not offered.
