# 2026-11-03: Practical enhancements, Priority 1 (GitHub issue #9)

Agreed in a grilling session on 2026-11-03. Plan only; no code yet. Built in this order, tests first.

## Decisions

### Step 1: Global Search
- One box in the top bar of every workspace page; Ctrl+K focuses it. Results open in a dropdown. (Trial: the owner will judge how it looks.)
- Searches services (theme, date, ministry name, song titles), events (title, venue), people (name only: `Person` has no email or phone), announcements (title).
- **Songs are left out for now (decided 2026-11-04).** There is no song library: every song added to a service creates a new `Song` row, so a song search would show duplicates, and `Song` stores no lyrics. A real song library gets its own plan, probably with Import (E4). Services search still finds a song by its title.
- Songs and Services have no grant module today, so every Member sees Services results. Events, Announcements and People results need the matching VIEW grant.
- Starts at 2 typed letters. At most 5 results per group. No separate results page for now.
- A group appears only if the user can view that module. Search never shows what the user could not open from the menu.
- Archived records are hidden by default, with an "Include archived" switch.
- Plain "contains" matching in Postgres. Move to full-text only if it feels slow or misses things.

### Step 2: Export
- New grantable **Export** permission. Off for Members by default, always on for Owner/Admin. A Member can only export modules they can also view (People data needs People view).
- **Full backup (JSON):** Owner/Admin only. Contains People (including birthdate, baptism, membership), Ministries, Songs, Services (blocks, songs, assignments), Events, Announcements, website pages and posts, templates and settings. Leaves out captions, usage data, error logs, sessions, and integration keys or secrets. Reserves a place for files so they can be added later without breaking old backups.
- **CSV per list:** grantable. Columns are tickboxes with plain names, useful ones pre-ticked. Sensitive People fields (birthdate, baptism, membership) are unticked by default.
- Every export is logged (who, when, what kind) in a new table shown to Owner/Admin in Settings. Entries older than 12 months are deleted by the daily keep-alive job. Needs an additive migration.
- Uploaded files are not in the backup yet (nothing writes `SongFile` or `ServiceAsset` today).

### Step 3: Templates
- "Save as template" on a service: copies block order and settings, not people or songs.
- "Copy event" on events. No separate event template system.

### Step 4: Import
- First slice: songs from a CSV file, with a preview and duplicate check before anything is saved.
- Restoring a JSON backup waits until export has proven itself.

### Step 5: Files
- Links first (Drive, YouTube, any web address) attached to songs and services only.
- Then small uploads (PDF or image, up to 10 MB) into the private bucket, with a per-church size cap. Large media is never uploaded.
- Facts found: `SongFile` and `ServiceAsset` exist in the schema but nothing reads or writes them. The one private bucket (`SUPABASE_PRIVATE_BUCKET`) holds only 24-hour uploads and generated outputs.

## Not decided here
- Event templates beyond "Copy event".
- Exact CSV column lists per list.
- Whether a grant for the full backup is ever wanted.
